# R04 — error ratio gated by traffic volume (draft for review)

Status: specification only. Scenario outputs below are proposed expectations,
not executed results. All inputs are controlled synthetic fixtures.

## Behavioural requirement — eligible for a future generation prompt

| Metric | Type and units | Meaning and complete input labels |
|---|---|---|
| `service_error_ratio` | Gauge; unitless fraction in [0,1] | Supplied error ratio; exactly `service` |
| `service_requests_last_minute` | Gauge; nonnegative integer number of requests | Supplied count for the preceding one-minute window; exactly `service` |

`service` is a nonempty string. There is exactly one series of each metric per
service, with the same service set for both metrics and stable labels. There
are no other input or external labels. The volume metric is a refreshed window
count that can rise or fall, not a cumulative counter or requests-per-second
rate. Use both gauges directly; do not derive rates, increases or window sums.
The supplied error ratio is finite even when supplied volume is zero; do not
divide by volume. This pilot evaluates the gauges, not their upstream computation.

Evaluate every minute at 0m, 1m, etc. Complete synchronized observations for
both metrics are available at every evaluation. Scenarios begin with no
pending or firing alerts; continuity means continuity at these evaluations.

For the **same service**, both conditions must hold together: error ratio
**strictly greater than 0.05** AND volume **greater than or equal to 100
requests in the preceding minute**. Require the conjunction to remain true
for **two elapsed minutes**. If either part becomes false, reset a pending
wait or clear a firing alert at that first false evaluation. No retention
applies. Neither condition alone, nor conditions satisfied by different
services, may trigger an alert.

Required alert name: `ServiceErrorRatioHighWithTraffic`. Emit exactly one alert
per affected service. Exact identifying labels: that `alertname` and the
original `service` value. No additional output labels or annotations are permitted.
