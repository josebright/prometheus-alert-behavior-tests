# R05 — production-only alerting (draft for review)

Status: specification only. Scenario outputs below are proposed expectations,
not executed results. All inputs are controlled synthetic fixtures.

## Behavioural requirement — eligible for a future generation prompt

Metric: `service_error_ratio`, a supplied gauge measured as a unitless fraction
in [0,1]. Complete input labels, excluding the implicit metric name: exactly
`service` (nonempty string) and `environment` (exactly `production` or `staging`,
case-sensitive). One series exists per declared (service, environment) pair.
Both environments may have the same service name. Labels and the declared
series set remain fixed; no other input or external labels exist. This task's
metric schema is intentionally different from R01; tasks run in isolation.

Evaluate every minute at 0m, 1m, etc. Each declared series has a finite sample
available at every evaluation. Scenarios start with no pending or firing
alerts. Use the ratio directly, without rate or other window calculations.

Only series with `environment="production"` are eligible. For each eligible
service, require the ratio to be **strictly greater than 0.05** for **two elapsed
minutes**, continuously at the scheduled evaluations. A false production
observation resets a pending wait or immediately clears a firing alert.
No additional retention applies. Staging values never start, prolong, reset
or clear a production alert, and must never produce any alert themselves.
Do not combine the two environments or different services.

Required alert name: `ProductionServiceErrorRatioHigh`. Emit exactly one alert
per affected production service. Exact identifying labels:
`alertname="ProductionServiceErrorRatioHigh"`, the original `service` value,
and `environment="production"`. No additional output labels or annotations
are permitted. The environment label must be retained.
